Route Story Studio · v0.2.0

Load a map background

Map backgrounds are optional and require a deliberate network request. Route Story Studio never loads map tiles merely because a route was imported.

Three-step flow

  1. Select Map background.
  2. Review the disclosure panel that moves into view.
  3. Press Consent and load map now. Export stays disabled until the map is successfully loaded.

What is sent

The browser requests only the tiles needed for the current route view. The request sends the website origin as the HTTP Referer, the browser's normal User-Agent and ordinary network metadata. No GPX, KML or project file is uploaded.

Responsible tile use

The application uses the official HTTPS tile URL, preserves visible attribution, honours browser caching, limits each map to nine tiles, loads at most two tiles concurrently and adds a short delay between requests. It does not prefetch zoom levels, build offline archives or disable caches.

Availability: OpenStreetMap's standard tile service is best-effort and may block requests. Route Story Studio detects HTTP 403 responses and the standard blocked-tile image, refuses to embed either in exports and presents recovery links.

If a map is blocked

  1. Refresh the deployed application so the current Referrer-Policy is active.
  2. Retry once. Do not repeatedly trigger map loading.
  3. Use a photograph or solid colour if the provider remains unavailable.
  4. Review the OpenStreetMap blocked-tiles guidance and tile usage policy.
  5. Report a persistent application issue in the project issue tracker.

Attribution

Every generated image using OpenStreetMap tiles includes © OpenStreetMap contributors. Attribution cannot be removed through the studio.
