Routing providers and credentials

The provider layer is designed so route intent is independent of any single routing service. The first adapter is openrouteservice.

What leaves the browser

When you resolve named places, the place text is sent to the provider. When you build a route, confirmed coordinates, waypoint order and travel mode are sent.

API key handling

  • The key is sent in the provider's Authorization header.
  • It is never included in a project, route, poster or application log.
  • By default it is stored for the browser session.
  • “Remember key” uses browser-local persistent storage.
  • “Clear saved key” revokes local storage immediately.

Provider behaviour

Coordinate inputs skip geocoding. Named places return up to five candidates and require user review. No silent fallback to another provider occurs.

openrouteservice directions POST endpoints can return GeoJSON LineString geometry, and its API accepts keys through the Authorization header.
